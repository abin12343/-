# 中盟账单数据整理

按《影刀中盟数据整理SOP(2)》实现：账单报价回填、天图核验、问题统计、运行记录和企业微信通知。

正常运行：

```powershell
python main_flow.py
```

按 SOP，登录中盟、筛选日期及导出文件不由脚本操作。直接运行时先弹出文件夹选择框，使用者选择装有全部账单的文件夹（当前为 `C:/Users/TT1/Desktop/中盟/中盟账单`），再弹出文件选择框选择本批次的数据列表；脚本递归批量处理其中的 `US*.xlsx`。`--pick-folder` 保留用于兼容；自动化运行可用 `--input-dir`、`--data-list` 指定路径，或加 `--no-dialog` 使用配置目录中的自动发现逻辑。

数据列表是必需文件，默认每批次单独弹窗选择。脚本使用 C 列客户单号、E 列分区在内存中完成匹配，将数值分区写到账单 Q 列；账单报价差异写入 S 列数值。数据列表“运费2”按 SOP 用 A 列渠道、E 列分区、H 列单件计费重，在报价表 C:J 区域以计费重匹配。处理后会把所选报价表复制到数据列表的隐藏页，U/V 使用本表内公式匹配，发送数据列表时不依赖外部报价表路径。无界面自动化时可用 `--data-list` 显式指定，或由脚本在目录中自动发现。

R 列空白不一定是匹配失败：如果整张账单存在“运费更正手续费”，或运费行属于已退件、件数不为 1，脚本按 SOP 跳过该表的运费报价；非报价类费用也不会强行填入 R。运行报告会分别列出“按 SOP 跳过运费”和“未匹配报价”。

`config.json` 的固定列对应 SOP：A 费用名称、F 费用金额、I 运单号、K 计费重、L 渠道、N 备注、O 件数、Q 分区、R 报价表、S 差异。正式运行前先用 `--dry-run --skip-tiantu --selftest` 检查报价匹配；真实天图核验需使用安装了 Playwright 的 Python（本机为 `D:/Anaconda/python.exe`）。企业微信与金山文档凭据将 `notify.example.json` 复制为同目录 `notify.local.json` 后填写，不要提交到仓库。

天图交付前双跑自检：

```powershell
D:/Anaconda/python.exe selftest_tiantu.py "outputs/中盟_天图核验清单_时间戳.csv" --online --limit 6
```

同一批任务连续查询两次，结论有任一翻转即返回失败，不应继续全量运行。

“超大件”按费用标题筛选，修正了 SOP 截图文字误写成“地址修正费”的问题。运费处理严格执行 SOP：同表存在“运费更正手续费”时整表运费跳过，同时排除 N=已退件和 O≠1 的行。住宅旺季附加费、不规则包装无论天图结果如何都登记统计表；补收住宅超大件同时核验“住宅私人”和“超长”。POD 会检查应收及费用明细中的“签收单”，地址修正按运踪中出现 `address` 或 `corrected` 判定。

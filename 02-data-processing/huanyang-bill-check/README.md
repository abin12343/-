# 环洋（HYE）打单账单数据整理

按《影刀环洋数据整理SOP》实现。参考 `02-data-processing/yongda-bill-check/`（永达）与
`02-data-processing/skye-bill-check/`（SKYE），实现/目录/交付形态一律照这两份来。

## 一、它做什么

```
账单1《成本汇总》xlsx ──┐
                       ├─→ 主单号 → 客户单号（去后缀 = 运单号）
账单2《成本明细》xlsx ──┘
        │
        ├─ ① 在「账单日期」右侧插一列「运单号」，填值（SOP 要求粘贴为值）
        ├─ ② 在「费用名称」右侧插三列「翻译 / 报价表 / 差异」
        │     翻译 = VLOOKUP 引用《打单费用名称中英文翻译》
        │     报价表 = 按 config.fee_rules 分派后引用报价表
        │     差异  = 报价表 − 费用
        │     （写公式还是写值，逐格先验算再定，见 §6）
        ├─ ③ 生成《环洋_天图核验清单》csv
        └─ ④ 交给 永达 check_tiantu.py 逐单核验
                 └─→ 查不到标记的 → 写入《打单问题统计表》的「环洋」页
                                      └─→ 企业微信 + 金山文档运行记录
```

**账单2 原地加工**，加工前备份成 `<名>_原始备份.xlsx`（已存在则往后编号，不覆盖）。

## 三、SOP → 代码映射

SOP 是给人工操作写的，原文有若干处对不上，逐条记录取值：

| SOP 原话 | 实现 | 说明 |
| --- | --- | --- |
| 「在账单1的 A 列右侧插入一行」+「在 G 列右侧插入 3 列」 | 只有**两处插列，都在账单2** | 原文把两张表混着说了。若 A 列插「运单号」使「费用名称」由 F 移到 G，再在 G 右侧插 3 列，正好得到 H=翻译 / I=报价表 / J=差异，与 SOP 后文「H 列筛选…在 I 列填写报价」「复制 B 列运单号」完全吻合。所以两处插列都落在账单2 |
| 「使用 VLOOKUP」（运单号那一步） | 用**值**回填 | SOP 对这一步明说「并且粘贴为值---后面账单2不再使用到」。跨工作簿引用一断就是满屏 `#REF!`，所以先建「主单号→客户单号」索引再回填值 |
| 「在 H 列**引用**『打单费用名称中英文翻译』表」 | 写 **VLOOKUP 公式** | SOP 原话是「引用」，即公式；永达也是这么做的。公式方案与安全闸门见 §6 |
| 「运单号分列后取前半段」 | `strip_waybill_suffix()` | 按 `_` 切，取前段 |
| 「H 列筛选费用名称，在 I 列填报价表」 | `config.fee_rules` 的 `zh` | 账单里「费用名称」是**英文**，SOP 那些中文类别名是「翻译」列的值 —— 所以链路是 `费用名称 → 翻译 → fee_rule → 报价表` |
| 「天图必须有红色『偏远』」 | `resolve_appearance()`（引擎内） | 红色类标记按颜色判，不是纯文本 |
| 「红色『偏远』+ 应收『住宅私人地址费』**二者缺一不可**」 | `tiantu` 写成**数组** | 一条规则配多个标记 → 拆成多条任务；任一条未查到就登记统计表 |
| 「差异」（列名就是这两个字） | `差异 = 报价表 − 费用` | 容差 `run.amount_tolerance`（0.05） |

## 四、`fee_rules`：SOP 表格怎么落到配置

每条规则 = SOP 表格里的一行。`kind` 只有两种：

- `base`（基础运费）：`ladder: commercial | residential`，按 **计费重 × 分区** 查阶梯；
- `surcharge`（附加费）：`items`（报价表里这个费用项可能叫什么）+ `section_prefer`
  （优先在哪一区块里找）。

`section_prefer` 存在的理由：同一张 sheet 里有「GROUND费用名称」「HOME DELIVERY费用名称」
「通用附加费」几块，**同一个费用项在不同区块价格不同**，住宅类必须优先落 HOME DELIVERY 那块。

注：`.xlsx` 报价表是人工维护的，区块标题会**截断/拼错** —— FedEx Ground-C 写
`HOME DELIVERY`，FedEx Ground-Q 写 `HOME DELIVER`（少个 Y）。所以区块名匹配是宽松的
（去空格后双向包含 + 前 6 字符前缀），见 `quote_engine._section_matches()`。
不这么做的话住宅类的价会全部落到商业区块（实测住宅附加费 2.38 vs 应为 6.65）。

## 五、报价表解析（`quote_engine.py`）

**不写死任何列号**，全靠两处文本线索定位：

1. **阶梯表**：某行有个单元格文本是 `lbs.`（重量表头），它右边紧接着一串
   `Zone 2 / Zone 3 / … / Zone 8 / Zone 44 / Zone 45 / Zone 46`。这一行就是表头行，
   下面是「重量 × 分区 → 单价」阶梯。
2. **附加费表**：某单元格 X 的**右邻居**文本含「收费标准」→ X 就是区块标题
   （费用名称 / GROUND费用名称 / HOME DELIVERY费用名称 / 通用附加费），右邻居列是价格列。

两个坑各留了一个守卫：

- `_looks_like_zone_label()`：价格格里写的是分区（`2区`）而不是价格。
  `to_float('2区')` 能抠出 `2.0`，只靠「能不能转成数字」判断会把分区号当价格读
  （超尺寸附加费会返回 2.0 而不是 18/19.95/23.1/24.3）。
- `Ladder.is_residential`：只看标题里的 `RESIDENTIAL` / `HOME DELIVERY`，**不看正文**。
  `Fedex Ground Commercial（住宅地址需要额外增加住宅附加费）` 的标题里带「住宅」，
  按子串判会被误标成住宅阶梯。

保底价（`Min` 行）按分区存成 `min_by_zone`，查价时 `max(价格, 保底)`；阶梯选择在
计费重 ≥ `quote.hwt_min_weight`（200）时优先百磅阶梯（UPS HWT 保底 86.0、
FedEx MTW-H 保底 80.85）。

三种版式都验证过：UPS GROUND-A/BD（两条阶梯 + 通用/HWT）、FedEx Ground-C（单阶梯 +
GROUND/HOME DELIVERY/通用）、FEDEX GROUND MTW-H（三条阶梯 + GROUND/HOME DELIVERY/MWT/通用）。
`--dry-run` 报告第六节会把每个 sheet 解析出的阶梯档位和区块打印出来，换报价表时先看那一节。

## 六、匹配列写成 Excel 公式（写之前先验算）

「翻译 / 报价表 / 差异」三列写的是**公式**，不是 Python 算好的值：

```
翻译   =VLOOKUP(TRIM(G2),'[打单费用名称中英文翻译.xlsx]Sheet1'!$A:$B,2,0)
报价表 =ROUND(INDEX('[报价表.xlsx]sheet'!$B$13:$B$162,
                    MATCH(CEILING($L2,1),'[报价表.xlsx]sheet'!$A$13:$A$162,1)),2)
       ='[报价表.xlsx]sheet'!$Z$19                  ← 附加费：直接指向那个价格子
差异   =ROUND(I2-F2,2)
```

好处是账单交出去之后改计费重、改报价表里的价，这三列会跟着变。代价是**跨工作簿引用一断
就是满屏 `#REF!`**，所以每一条公式在写下去之前都要过一道闸门。

### 外部引用只有两种写法

Excel 的中括号里只认**裸文件名**（按**引用方工作簿自己所在的目录**解析）或**完整绝对路径**
（目录在中括号**外面**：`'C:\dir\[表.xlsx]sheet'!`）。**没有 `..\` 这种父目录相对写法**——
永达的 SOP 只写裸文件名、其脚本宁可用「把报价表复制到账单旁边」来兜，正是因为相对路径
走不通。所以本工具的规矩是：

| 报价表 / 翻译表的位置 | 写什么 |
| --- | --- |
| 与账单**同目录**（日常情形） | 裸文件名公式 |
| **不同目录** | 该列**退回写值**（绝不写绝对路径，也绝不往你的目录里塞副本） |

默认**永远不出现绝对路径**。要是就是想让它永远写公式，把
`run.write_formulas_allow_absolute` 改成 `true`，那时不同目录才写绝对路径。

> ⚠️ **翻译表比较特别**：发布包自带一份，而账单文件夹里往往也有一份。公式里的裸文件名是
> 给 Excel 看的，它会去**账单旁边**找同名文件——所以验算也按账单旁边那份来，找不到才退回写值。

### 每一条公式都先按 Excel 的规矩验算过

`FormulaGate`（`process_details.py`）逐格判定：验算通过才写公式，否则写值并把原因记进报告
第七节。几处刻意的地方：

- **基础运费**：`MATCH(...,1)` 要求重量列**原表升序**。引擎解析时会把降序表 `sort()` 掉，
  公式不会——所以只有「原表升序 + 区间连续 + 档位是纯数字」的阶梯才写公式。
  `IFERROR` **只在计费重确实低于第一档时**才裹，否则它会把断链的 `#REF!` 也吞成第一档的价，
  那是静默的错价。保底价写**单元格**不写字面量；取整用 `TRUNC` 而不是 `INT`
  （Excel 的 `INT` 是向下取整，Python 的 `int()` 是向零截断）。
- **附加费**：**直接指向**那个价格单元格，不做 `MATCH`。区块内的项名匹配是去空白、忽略
  大小写、还带子串兜底的，`MATCH` 复刻不了；引擎已经把确切出处解析出来了，指过去更忠实。
- **翻译**：按 VLOOKUP 的首匹配语义验算。Excel 的 VLOOKUP **大小写不敏感**、文本与数字还会
  互相靠拢，这些宽松规则只要有可能影响落点就退回写值。实测翻译表 113 个键里
  `DAS Extended Resi` 就是这种（表里有重复键），它出现时写值不写公式。
- **计费重那一格**：Excel 会把「看着像数字的文本」当数字用（账单导出来整列计费重都是
  `'26.000'`，`CEILING("26.000",1)` 照样是 27），所以不能一刀切拒掉；但带千分位的
  `'1,234.5'`、带单位的 `'26 lbs'` 在 Excel 里是 `#VALUE!`，这些退回写值。

### 活性边界（交付前必须知道）

公式只对**它读的那几格**敏感：

| 你改了什么 | 三列会跟着变吗 |
| --- | --- |
| 账单的**计费重** | ✅ 会 |
| 报价表里的**价格** | ✅ 会 |
| 账单的**分区** / **产品名称** | ❌ 不会（公式选哪一段阶梯、哪一列，是写公式那一刻定的） |
| 报价表**插行 / 改结构** | ❌ 会整体错位（引擎按文字线索重新定位，公式不会） |
| 计费重**跨过 200lb** | ❌ 不会自动改用百磅阶梯，**要重跑一次工具** |

最后一条是有意为之：百磅 / MWT 是另一段表，切换规则在引擎里，公式复刻不了。跨阈值就重跑，
工具会重新选段并重写公式。

另外两点：

- **公式格没有缓存值**。openpyxl 写公式时不写计算结果，所以用「只读缓存值」的方式
  （`data_only=True`）打开产物会看到这三列是空的。用 Excel 打开就正常。
- **Excel 打开时会问「是否更新链接」**，点**更新**。不更新的话这三列显示的是上次的缓存值。

## 七、天图核验与自测

天图那一段**不重写**，直接用 永达的 `check_tiantu.py`，以子进程方式驱动，
契约是那份 CSV 清单（`客户单号(去后缀) / 费用名称 / 期望标记`）。引擎输出
`天图核验结果_*.csv`（`单号 / 费用名称 / 期望标记 / 是否出现 / 命中条数 / 明细 / 缺失关键词`）。

三件容易踩的事，`main_flow.py` 里都处理了：

1. **结果目录要找两处**：引擎把结果写到**它自己** `config.json` 的 `output_dir`，
   不是我们的 `outputs`。发布包里两者恰好是同一个（发布根/outputs），源码态则不是
   （永达目录/outputs）。`_tiantu_dirs()` 两个都搜。
2. **凭证位置**：`run_yongda_check.load_credentials` 冻结态取
   `sys.executable` 的父目录的**父目录**当根，所以发布包里 `credentials.local.json`
   必须在**发布根**，不在 `check_tiantu/` 里。`_engine_base()` 复刻这个规则，
   自测的契约检查也用同一个根去找，避免"检查通过、真跑失败"。
3. **卡死判定靠静默**：总时长上限只能按清单长度估（`批次数 × per_batch + 逐单条数 × per_waybill + 180`），
   估小了会把还在正常干活的引擎杀掉、整轮白跑。真正的中止依据是
   `tiantu.idle_seconds`（默认 300）秒内没有任何输出。子进程输出同时进控制台和
   `outputs/环洋_天图运行_<时间戳>.log`。

`--selftest`（或直接 `python selftest_tiantu.py`）跑两层：

- **A 契约自检（离线、秒出）**：引擎在不在、凭证在不在且字段全不全、清单字段全不全、
  **每个期望标记引擎认不认识**。最后一条是最要紧的：引擎只对 `住宅私人`、`address`、
  `偏远/超偏远/超长/超重` 有专门分支，写错一个字会退化成"整段文本里找这个词"、恒判「否」——
  这种错从结果上看不出来，只表现为"这单天图确实没有"。
- **B 双跑一致性（联网）**：抽 `selftest.limit` 个单号（按 `selftest.marks` 优先、
  其余按各类数量轮流取，保证覆盖到多种标记），**连跑两遍**，按 `(单号, 期望标记)`
  逐条比对，报告 **翻转条数**。

  天图的应收格子内容是**异步填的**，历史上出现过「读一次读空就当否」导致同一批单号
  两次结论不一致（SKYE 那边实测 4 个 是→否 翻转；引擎按 rowid 认行 + 轮询 + 关残留弹层
  修掉后 24/24 一致）。所以翻转 0 条才是「判定稳定」的证据。

  报告同时打印按标记拆分的「条数/翻转」，以及每次运行的查询次数与耗时
  （`summarize_tiantu_log()` 从引擎日志里数 `[批] … x\d+ -> `、`拆半(重试|补查)`、
  `单查 `、`应收核验 `、`地址更正核验 `、`[对账补查]`）。天图慢只慢在查询次数上。

## 八、打包

见 `release/打包.py`（一键）与各 `.spec`。布局照 SKYE：

```
环洋账单整理工具_EXE版/
  HuanyangTool/   main_flow/   check_tiantu/     ← 三个 onedir
  config.json  credentials.local.json  notify.local.json
  打单费用名称中英文翻译.xlsx  outputs/  logs/  启动环洋工具.bat  使用说明.md
```

- `main_flow.spec` 的 `excludes` 排除 `playwright`（只有引擎需要它），
  `hiddenimports` 点名 `autolib.dialog / excel / notify`（延迟 import，静态扫不到）。
- `check_tiantu.spec` 的 `pathex` 必须带**永达目录**：引擎 `import run_yongda_check.load_credentials`。
- 发布根的 `config.json` 与开发目录那份只差 `paths` 段（`output_dir: "outputs"`，
  相对发布根）。它**同时被主流程和引擎读**（引擎只取 `paths.output_dir`），
  所以不能写死开发机绝对路径。
- `credentials.local.json` 由 `打包.py` 从永达那份里**只取 `tiantu_user/tiantu_pass`** 生成 ——
  永达那份还带着打单系统账号，环洋流程用不到，没必要跟着发出去。

## 九、实测基线（2026-09-17，`深圳市心一供应链有限公司(HYE0356)2026-09-02`）

```
总行数 2575 / 填出运单号 2575（缺失 0）/ 已翻译 2575（无翻译 0）
已填报价 376 / 未匹配报价 0 / 零额行跳过 35 / 差异超容差 1
公式列 翻译 2575 / 报价 376 / 差异 376（退回写值 0）
天图核验任务 174 条，涉及单号 147 个（其中 46 条走逐单核验）
```

唯一那条差异是**真实的账单差异**，不是查价错：
`USSZAS2607100010` 住宅附加费，产品 `美西 Fedex Ground-Q`，计费重 32、分区 8，
账单收了 6.64，而该 sheet 的 HOME DELIVER 区块价是 2.38（差 −4.26）。

SOP 给的那个数据点也复现了：`美中UPS GROUND-BD` / 计费重 26.000 / 分区 02 /
费用 6.26 → 报价表 6.26、差异 0。

## 十、与 SKYE / 永达的差异

| 项 | 永达 | SKYE | 环洋 |
| --- | --- | --- | --- |
| 账单来源 | 打单系统导出（`fetch_bill.py` 登录下载） | 同左 | **桌面 xlsx**，不需登录 |
| 弹窗 | — | 账单 / 报价表 / 统计表 | **四个**：账单1、账单2、报价表、统计表 |
| 加工方式 | 加工列写回原账单 | 只加 sheet，不动原表 | 插列写回原账单（同永达） |
